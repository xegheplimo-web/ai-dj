## What changed, file by file

- **`ai_dj/analysis/beatgrid.py`** (new): `BEAT_HOP_LENGTH = 128` (5.805 ms frames at
  22.05 kHz, was 512 → 23.220 ms); `fit_beat_grid` — least-squares `beat_index → time`
  fit over all detected beats; `refined_grid` — rebuilt continuous grid `a·i + b`;
  `bpm_resolution` — 1σ BPM resolution of the LS slope under frame quantization,
  `σ_bpm = (60/ibi²)·p/√(n³−n)`; `assess_quality` — per-track quality block (below);
  `BEAT_GRID_VERSION = 2` (v1 = legacy frame-snapped grid in v3 payloads).
- **`ai_dj/analysis/analyzer.py`**: `ANALYSIS_VERSION` 3 → 4. Beat/onset stage
  extracted into `_beat_grid_fields`, running `onset_strength` + `beat_track` at
  hop 128 while chroma/RMS keep hop 512. New payload fields: `beat_grid_version`,
  `beat_hop_length`, `beat_frame_period_ms`, `bpm_ibi_median` (old-style median-IBI
  value for comparison), `bpm_refined`, `bpm_resolution`, `median_ibi_detected_s`,
  `beat_times_detected_s`, `beat_quality{…}`. Compatibility fields preserved:
  `bpm_raw`, `bpm_corrected`, `median_ibi_s`, `beat_times_s`, `downbeat_times_s`,
  `ibi_cv`, `tempo_confidence`, `n_beats`. `median_ibi_s` now comes from the refined
  grid (continuous, off both rasters).
- **`ai_dj/continuity.py`**: `has_continuity_payload` now requires
  `beat_grid_version == BEAT_GRID_VERSION` in addition to `continuity_version` —
  a v3 record is *unmeasured* under v4, so `plan` fails closed
  (`ANALYSIS_REQUIRED`/`CORPUS_UNMEASURED`, exit 5) and v3/v4 can never mix.
  No other continuity logic touched.
- **`tests/test_beatgrid.py`** (new, 18 tests): LS-fit math, off-ladder recovery,
  payload contract, quality flags (coverage, tempo step, octave, fabricated grid),
  v3-staleness + CLI plan fail-closed; plus `--emit-evidence` harness producing the
  corpus before/after report and the three-tier independent validation.
- **`tests/test_continuity.py`, `tests/test_hardening.py`**: contract fixtures gain
  `beat_grid_version` (v4-complete records).
- **`tests/test_predictor_adversarial.py`**: runtime-built predictor records gain
  `beat_grid_version` so they remain "measured" under the new gate.
- **`planner.py`: NOT modified** (per constraint). No D6/D12 threshold touched.
  No dependencies added.

## Quality gate — proposed thresholds with corpus justification

Measured on all 41 ok-status v4 records (`evidence/analysis_cache_v4.sqlite`).
`status` is **informational** (D25: no hard rejection; `plan` does not consume it).

| Metric | Threshold | Corpus min / median / p95 / max | Outcome |
|---|---|---|---|
| `residual_std_ms` | warn > 20 ms | 16.0 / 137.8 / 596.7 / 1182.1 | fires on 39/41 — this corpus is live covers whose real tempo wanders; 20 ms is the D6 contract value the shipped constant grid must support |
| `coverage_ratio` | < 0.85 or > 1.15 | 0.949 / 0.993 / 1.010 / 1.029 | no corpus fires; synthetic dropped/over-detection cases hit 0.5 / 2.0 — discriminating band |
| `phase_drift_ms` | > 40 ms | −230.3 / 3.6 / 225.9 / 801.4 | 2× the contract; catches monotone phase walk the LS slope hides |
| `ibi_drift_pct` | > 5 % | −3.85 / 0.0 / 1.67 / 3.49 | just above corpus extremes; synthetic tempo step gave −10 % |
| `residual_growth_ratio` | > 1.75 | 0.44 / 0.99 / 4.02 / 5.13 | fires where late-half jitter exceeds early-half (detection decay) |
| `beat_env_ratio` | < 2.0 | 3.40 / 6.10 / 8.98 / 9.73 | separates "beats land on transients" from fabricated grids: sustained tone ≈ 1.0, white noise ≈ 1.3 |
| `octave_suspect` | refined vs `bpm_raw` disagree | 0/41 fires | synthetic disagreement cases flag correctly |

**Honest reading of the corpus outcome:** 39/41 tracks are `suspect`, dominated by
`residual_std_ms`/`tempo_unstable`. These are human-played covers without click
reference; a single constant tempo genuinely does not fit them at ±20 ms. The gate
correctly *reports* this instead of trusting the fit — tempo estimates remain
accurate (see validation) while beat-instant grids are honestly labeled loose.

## Independent accuracy validation (`evidence/beat_grid_synthetic_validation.json`)

Ground truth is decided **before** analysis in every tier — never the estimator's
own output (D6/D25 non-circular rule).

- **T1 click sweep, 41 tempos 88–180 BPM incl. off-ladder (122.5, 128.5→see T2,
  161.484, 166.686, 172.267):** 37/41 within **≤0.011 BPM** of truth; grid-to-truth
  median ≈ 11–16 ms (a constant ~14 ms phase offset = onset-envelope latency,
  inside the 20 ms contract). **4 failures**: 168/174/178/180 BPM clicks return
  exactly half (83.995/87.004/88.998/90.003; `octave_diagnosis = agree` because
  `beat_track` itself chooses the half-time level upstream — see Limitations).
- **T2 musical patterns** (kick/snare/hi-hat; swing, half-time, four-on-floor,
  missing every 4th beat): all 8 within **≤0.097 BPM**; `offladder_166_686` and
  `four_on_floor_126` additionally carry `suspect` flags.
- **T2n negative material** (white noise, pure 220 Hz tone, aperiodic clicks): all
  flagged `suspect` — including the pure tone, where `beat_track` fabricated a
  regular grid (residual 1.7 ms, coverage 1.01) that only `beat_env_ratio`
  (≈1.0 < 2.0) exposes. `tempo_confidence` itself stays 0.7–0.9 there — the new
  quality block, not the old confidence, carries the negative-case signal.
- **Corpus onset-landmark check** (peak-picked onsets on a hop-512 envelope,
  independent of the hop-128 detector and the LS fit): v3 grid medians rail to
  exact 23.22 ms multiples (46.4/69.7/92.9/116.1) because landmarks share the v3
  raster — the *measurement* was quantized. Median nearest-landmark distance
  69.7 ms (v3) vs 91.7 ms (v4-fitted); **within-20 ms beat fraction 0.24 % →
  11.4 %** (47×). The fitted constant grid drifts farther on wandering tracks than
  raw detections do — the quality block flags exactly those tracks.

## Acceptance criteria

1. **`median_ibi_s` off the legacy raster:** yes — 0/41 records on a
   23.22 ms multiple (v4 cache check); T1 sweep: 39/41 off-raster, the 2
   exceptions (136.0, 172.267) sit exactly on the legacy ladder *by construction*.
2. **BPM resolution < 1 (80–180):** max observed `bpm_resolution` = **0.00061**.
3. **Quality metrics on every track:** `beat_quality` present on all 42 rows
   (2 additionally `insufficient_beats`-capable fields included).
4. **v3 stale, plan fails closed:** demonstrated on the real v3 cache (exit 5,
   `CORPUS_UNMEASURED`) and on a deliberately mixed cache (exit 5,
   `ANALYSIS_REQUIRED` naming the stale id). Unit tests pin both.
5. **Existing tests:** 121/121 still pass (139 total with new tests).
6. **Ruff:** `check` + `format --check` clean repo-wide.
7. **Timing probe:** 0.2037 ms ≤ 20 ms (unchanged from 0.204 baseline).
8. **D12 mini-set:** plan → render → verify on v4 cache = **PASS**
   (silence gates ok; synthetic alignment 0.0 ms).
9. **Before/after report:** `evidence/beat_grid_before_after.json` + `.md` (41 tracks).
10. **Independent confirmation:** three-tier known-answer suite + corpus
    onset-landmark check — see above. Tempo accuracy proven to ≤0.05 BPM on
    constant-tempo material; per-beat grid placement on this wandering live
    corpus is honestly marked `suspect`.

## Limitations / not verified

- **Half-time detector choice above ~166 BPM on click tracks** (T1: 168–180 →
  half values, `octave_diagnosis = agree`): `beat_track`'s metrical level is wrong
  upstream of the grid work, and the halved grid is self-consistent (residuals ~0,
  coverage ~1, env support fine) so within-track metrics cannot flag it. Real
  corpus unaffected (all `agree`; refined range 84–170 plausible), but a
  tempo-prior or autocorrelation check would be needed to catch it.
- **39/41 corpus tracks `suspect`** is the truthful answer for live covers under a
  constant-tempo model; if that is too noisy for planning UX, a follow-up card
  could add a piecewise/local-tempo grid — out of scope here.
- `v3→v4` delta distribution includes real detection changes (hop 512→128 changes
  `beat_track`'s picks), not pure dequantization — expected and disclosed.
- The committed `analysis_cache.sqlite` remains v3; `plan` on it now fails closed
  as designed. The orchestrator decides when the primary cache is re-analyzed.
- `evidence/master_beatgrid_v4.wav` is produced but unlisted by `git status`
  (covered by existing ignore rules).
- `phase_drift_ms` was initially implemented as an LS-residual slope — degenerate
  (identically 0 by construction); replaced with edge-median residual difference
  (corpus: median 3.6 ms, p95 226 ms).
