# DJ-P2-OCTAVE-001 — agent report

Multi-hypothesis octave resolution (D26 §7.1) + bounded, scale-invariant
envelope-support score (F2), with explicit `octave_ambiguous` reporting (B1).

## What changed, per file

### `ai_dj/analysis/beatgrid.py`

- `BEAT_GRID_VERSION` 2 → **3** (`beatgrid.py:30`) — shipped grids now encode the
  resolved octave level, so every pre-existing record is stale.
- `beat_env_score(onset_env, beat_frames)` (`beatgrid.py:103`) replaces the
  unbounded `beat_env_ratio`. It computes `medB / (medB + med_env + eps)` with
  `eps = 1e-9 * max(env)` — the monotone image `r/(1+r)` of the old ratio,
  bounded to `[0, 1)` and exactly scale-invariant. The old fabrication gate
  `ratio >= 2.0` maps exactly to `score >= BEAT_ENV_SCORE_MIN = 2/3`
  (`beatgrid.py:47`); ordering and the pass/fail boundary are unchanged.
- `resolve_octave_level(...)` (`beatgrid.py:190`): evaluates `OCTAVE_LEVELS =
  {0.5, 1.0, 2.0}` for the detected tempo. Each hypothesis is scored as
  `acf_norm + 0.25*strength + 0.20*prior − 0.35*anti_penalty`, where
  `acf_norm` is the interpolated onset-envelope autocorrelation at the
  candidate period (normalised by the zero-lag value), `strength` is the median
  envelope under the candidate's comb teeth, `prior` is a weak log-domain tempo
  prior centred at 128 BPM, and `anti_penalty` punishes grids whose off-phase
  positions sit on onsets the grid misses. If top-vs-runner-up margin is below
  `OCTAVE_AMBIGUITY_MARGIN = 0.08` (`beatgrid.py:56,286`) the detected level is
  kept but the result is `ambiguous` — a declared cannot-determine, never a
  silent guess. Per-candidate diagnostics (scores, acf, tooth/anti medians) are
  returned for audit.
- `assess_quality(...)` (`beatgrid.py:333`): emits `beat_env_score` instead of
  `beat_env_ratio`, takes the new `octave_ambiguous` flag, appends an explicit
  `octave_ambiguous` reason and forces `suspect` when the level could not be
  verified (`beatgrid.py:430,447,467`).

### `ai_dj/analysis/analyzer.py`

- `ANALYSIS_VERSION` 4 → **5** (`analyzer.py:54`); docstring updated.
- Fits the detected grid first (`bpm_detected`), calls
  `resolve_octave_level` (`analyzer.py:237`), then rebuilds the shipped grid at
  the selected level: ×2 interleaves midpoint beats (~`2n−1` shipped beats),
  ×0.5 keeps the stronger parity (every other detected beat), ×1 unchanged. LS
  refinement itself is untouched.
- Provenance: `bpm_detected`, `beat_times_detected_s`, `median_ibi_detected_s`
  preserve the raw detected grid; `bpm_refined`/`bpm_corrected`/`median_ibi_s`/
  `beat_times_s`/`downbeat_times_s` ship the resolved level (`analyzer.py:315`).
  `octave_diagnosis` now carries the resolver's full diagnostic dict; the old
  raw-vs-detected comparison is preserved as `raw_vs_detected`.
- `tempo_confidence` is capped at 0.4 when the resolver is ambiguous — below
  the planner's 0.5 beatmatching floor, so an unverified tempo cannot produce a
  `beatmatched` transition (D26 §6).

### `tests/test_beatgrid.py`

- Existing tests updated from `beat_env_ratio` to `beat_env_score`
  (`test_beatgrid.py:140,162,166,179`).
- New `TestBoundedBeatEnvScore` (5 tests): finite/bounded on sparse envelopes,
  exact scale invariance, old-threshold mapping (score 2/3 ≡ ratio 2.0),

- New `TestOctaveResolution` (6 tests): all three factors evaluated; the four
