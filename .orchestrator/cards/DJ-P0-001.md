## 1. Kiến trúc đã chốt (D1–D9, bắt buộc tuân thủ)

```
Thư viện nhạc (F:\DỮ LIỆU\ok, WAV/MP3)
   ↓  [1] Analyzer (librosa) → BPM + key + downbeat + energy + intro/outro, cache sqlite
   ↓  [2] Planner (deterministic) → plan.json: thứ tự bài, loại transition, cue vào/ra, energy arc
   ↓  [3] Renderer (deterministic, sample-accurate) → beat-align + ffmpeg rubberband + EQ + crossfade
   ↓  [4] Player (PCM playback từ bản đã render) → sounddevice
   ↓  master WAV (bằng chứng) + phát realtime
```

Các ràng buộc cứng:
1. **KHÔNG dùng Mixxx, KHÔNG dùng driver MIDI/loopMIDI** (D5). Engine là Python thuần.
2. **KHÔNG đưa LLM vào P0** (D3). Planner phải deterministic, confidence-aware, tái lập được
   từ cùng corpus + cùng seed → plan.json byte-identical.
3. **KHÔNG làm DSP trong audio callback** (D2). PortAudio cấm allocation/filesystem I/O trong callback
   realtime. Player chỉ đọc block PCM đã dựng sẵn (ring buffer điền từ thread khác).
4. **Timing theo sample index** trên một timeline chung 48 kHz (D9). Không dùng `time.sleep()`
   để quyết định thời điểm mix.
5. **Chỉ thêm dependency đã có trong `requirements.txt`** (numpy, librosa, soundfile, sounddevice).
   Cần thêm thì phải ghi rõ lý do trong báo cáo — Hermes quyết.
6. **Không sửa `ai_dj/timing.py`** (harness đo độc lập, Hermes sở hữu). Có thể import lại.
7. **KHÔNG ghi/tạo file trong `.devin/`** (sẽ làm phiên chết giữa chừng).
8. **KHÔNG commit** — Hermes sở hữu git. Bạn chỉ sửa/thêm file trong working tree.

## 2. Việc cần làm (theo thứ tự, mỗi bước phải chạy được trước khi sang bước sau)

### G0 — Khởi động + corpus scan
- `ai_dj/analysis/corpus.py`: quét thư mục nhạc, phát hiện file WAV/MP3, trả về danh sách
  `TrackRef{path, title, recording_id, work_id}`. Phải xử lý được đường dẫn tiếng Việt có dấu.
- **D8 (bắt buộc):** tách `recording_id` (bản thu — riêng theo file) và `work_id` (tác phẩm —
  cùng một bài hát cover bởi nhiều người = cùng `work_id`). 55 file ≠ 55 bài độc lập; phải có
  heuristic gom nhóm (ví dụ: chuẩn hoá tên bài + nghệ sĩ) và ghi rõ heuristic đó trong docstring.
  `work_id` phải là **tính phái sinh deterministic** từ nội dung metadata, không phải phỏng đoán.
- `ai_dj/cli.py`: CLI dùng `argparse`, các lệnh: `scan`, `analyze`, `plan`, `render`, `play`, `verify`.
  Mỗi lệnh phải in JSON hoặc thông báo lỗi rõ ràng, exit code 0/1/2 hợp lý.

### G1 — Analyzer
- `ai_dj/analysis/analyzer.py`: với mỗi track, tính **BPM, musical key, downbeat grid, energy theo
  thời gian, intro/outro region**, lưu cache sqlite (`.cache/analysis.sqlite`).
- **Bắt buộc xử lý lỗi octave** (đo được: `librosa.feature.tempo` trả 92–144 BPM cho Bolero).
  Dùng trung vị IBI + chẩn đoán octave; ghi cả BPM thô và BPM đã hiệu chỉnh vào cache.
- Cache phải ổn định: chạy lại `analyze` hai lần phải cho kết quả giống hệt (idempotent).
- Khi `librosa` không phân tích được 1 file: ghi lỗi vào cache, **KHÔNG** làm hỏng cả corpus.

### G2 — Planner
- `ai_dj/planner.py`: sinh `plan.json` cho 1 set 6–8 bài (mini-set) từ corpus đã phân tích.
  Input: mood/thể loại/energy target (CLI args, mặc định hợp lý). Output: thứ tự bài, loại
  transition cho từng cặp (cut / crossfade / echo-out), cue vào/ra theo **số sample**, energy arc.
- Deterministic: cùng input + cùng cache → `plan.json` byte-identical (không dùng thời gian hệ thống,
  không dùng hash của dict order, không dùng RNG không seed).
- Confidence-aware: với cặp bài không tương thích (key lệch xa, BPM lệch quá ngưỡng), planner phải
  **tự chọn cách chuyển an toàn** (ví dụ cut thay vì beatmatch) và ghi `confidence` + `reason`.
  Không được ép beatmatch hai bài không tương thích (G2b yêu cầu không có forced beatmatch).

### G3 — Renderer
- `ai_dj/render.py`: dựng master timeline từ `plan.json` → master WAV mono/stereo 48 kHz.
  Dùng `ffmpeg rubberband` cho time-stretch khi cần beat-align; crossfade/cut theo sample index.
  Đọc lại WAV master và ghi `evidence/render_report.json`: số sample, duration, true peak (dBTP),
  clipping count, số underflow (nếu có), độ lệch beat so với plan (đo bằng `ai_dj.timing`).
- **KHÔNG dùng `time.sleep()` trong đường render.**

### G4 — Player
- `ai_dj/player.py`: phát master WAV qua `sounddevice` theo block PCM (ring buffer + thread),
  không DSP trong callback. Có cơ chế dừng an toàn (Ctrl-C / flag).
- Phát phải khớp với bản render (cùng file, cùng thứ tự) — không tái tính lại gì lúc phát.

## 3. Acceptance criteria (TẤT CẢ phải đạt; bạn phải chạy thật và dán kết quả)

1. `python -m ruff check .` → **All checks passed**
2. `python -m ruff format --check .` → **all files already formatted**
3. `python -m unittest discover -s tests -v` → **OK, không FAIL/ERROR**
4. `python scripts/timing_probe.py --bpm 120 --tempo 1.08` → exit 0 (harness cũ vẫn xanh)
5. Test MỚI cho analyzer/planner/renderer phải **deterministic**: chạy 2 lần → kết quả giống hệt
6. `python -m ai_dj.cli scan --dir "F:\DỮ LIỆU\ok"` → JSON danh sách track, exit 0
7. `python -m ai_dj.cli plan --set-name mini --tracks 6` → `evidence/plan.json`, deterministic
8. `python -m ai_dj.cli render --plan evidence/plan.json --out evidence/mini_set.wav` → WAV thật
   + `evidence/render_report.json` với: true peak ≤ −1 dBTP, clipping count = 0, duration ≈ tổng
   thời lượng bài, beat deviation ≤ 20 ms theo `ai_dj.timing`
9. `python -m ai_dj.cli verify --plan evidence/plan.json --master evidence/mini_set.wav` → exit 0
   và ghi `evidence/verification.json` (không được lấy timing do engine tự khai báo làm bằng chứng duy nhất
   — phải đo lại từ WAV master, xem `ai_dj/timing.py`)
10. Báo cáo cuối: danh sách file đã tạo/sửa, kết quả chạy từng acceptance ở trên (dán nguyên output),
    các giới hạn còn lại, và mọi thứ bạn đã phát hiện nhưng KHÔNG sửa (để Hermes quyết).
