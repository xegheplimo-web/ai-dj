## 1. Gap 1 — two-tier silence thresholds (D12 refinement)

DJ-P0-006 used a single threshold (`SILENCE_PEAK = 1e-4` ≈ −80 dBFS, `MAX_SILENT_RUN_MS = 100`).
That misses a **low-level near-silence** stretch: audio at −60 dBFS for 2 s is effectively
inaudible in a DJ set but is nowhere near digital silence.

Implement two independent classes on 50 ms RMS blocks, over the **entire** master:

| Class | Level | Min run | Result |
|---|---|---|---|
| Digital / near-digital silence | ≤ −90 dBFS | ≥ 0.5 s | **FAIL** |
| Low-level near-silence | ≤ −60 dBFS | ≥ 2.0 s | **FAIL** |
| Short-term loudness (3 s window) | — | — | diagnostic only |

Keep the transition-window figure as a diagnostic.

### Rule A — multi-channel RMS, never mono

`mono = data.mean(axis=1)` is WRONG: anti-phase L/R cancels toward zero while both
channels carry real audio. Compute

```
RMS = sqrt( sum_c sum_n x[n,c]^2 / (N*C) )
```

then convert to dBFS. Also report per-channel RMS and flag a dead channel separately.

### Rule B — fade exemption from the renderer's real sample range

Do not exempt an arbitrary first/last N seconds. Exempt only samples inside the fade-in/out
the renderer actually declared (already implemented via `MASTER_FADE_IN_S` /
`MASTER_FADE_OUT_S`). Every region inside an exempt range still appears in the report.

### Rule C — run length in samples

All threshold comparisons use sample index at the master's sample rate; state `>=`
explicitly; add boundary fixtures at exactly 0.5 s and 2.0 s.

## 2. Gap 2 — a missing required artifact is FAIL, not a usage error

Measured: `verify --master <nonexistent>` exits **2** (generic exception path).
A required artifact that is absent, corrupt, or undecodable must be **FAIL** (`pass: false`,
`verdict: "FAIL"`), not INCONCLUSIVE and not a usage error. Only *unmeasurable* things
(no ffmpeg, no reference) are INCONCLUSIVE.

## 3. Gap 3 — make exit codes unambiguous

Today exit **2** serves both INCONCLUSIVE and usage/environment errors, so a caller
cannot distinguish "we could not measure" from "you invoked it wrong".

Contract:

| Condition | `pass` | exit |
|---|---|---|
| every required check measured and within contract | `true` | 0 |
| at least one required check measured and failed | `false` | 1 |
| no FAIL, but a required measurement is missing | `null` | 3 |
| CLI usage / environment error | — | 2 |

Keep 2 for usage errors (argparse convention, already documented in `cli.py`).
A usage error must not emit a report with a valid-looking verdict.

**FAIL must never be masked by INCONCLUSIVE**: ffmpeg absent *and* a confirmed hole → FAIL.
