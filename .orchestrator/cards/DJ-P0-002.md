# DJ-P0-002 — Corpus eligibility rule (fix the non-song defect)

**Parent:** DJ-P0-001 (merged as `a52099a`)
**Owner:** Hermes (technical owner) · **Coder:** Devin CLI
**Status:** ready

---

## 1. Problem (VERIFIED by Hermes, not inferred)

The planner can select files that are not songs. One such file opened the demo
set and produced a **29.4 s silent gap** inside the rendered master.

Measured independently by Hermes (`corpus_audit.py`, -100 dB RMS, 50 ms blocks):

| file | silence | silence inside runs > 2 s | top silent runs |
|---|---|---|---|
| `huan luyen.wav` | 32.0 % | **31.9 %** | 46.8 s @ 0 s, 36.4 s @ 317 s, 29.4 s @ 139 s |
| `ĐỐI DIỆN NHÀ EM - DUY GỐC.wav` | 21.9 % | **21.8 %** | 40.3 s @ 170 s, 30.0 s @ 4 s |
| `Khóa Ly Biệt (Cover Duy).wav` | 0.2 % | **0.0 %** | 0.3 s |
| `Chuyện tình cô lái đò-Bolero(Cover Duy).wav` | 0.0 % | **0.0 %** | none |
| `Untitled Session 32_mixdown.wav` | 0.1 % | **0.0 %** | 0.2 s |

Real songs sit at 0.0–0.2 %; non-songs at 21.8–31.9 %. The separation is ~100x,
so a threshold is safe.

Rendered proof: `evidence/hermes_set.wav` contains a silent run 90.00 s →
119.30 s (29.40 s), located **inside** the first track (`huan luyen`), not at a
transition (transition 0 sits at 243.95–249.52 s).

## 2. Decision (Hermes — D10)

Add an **eligibility rule** based on the measured quantity above:

```
MAX_SILENCE_RUN_FRACTION = 0.02   # 2 % of duration may sit in silent runs > 2 s
MIN_SILENCE_RUN_S        = 2.0    # a "run" is a contiguous silent stretch
SILENCE_DB              = 100.0  # -100 dB RMS counts as silence
SILENCE_BLOCK_S         = 0.05   # 50 ms analysis block
```

A track is **eligible** iff `silence_run_ratio <= MAX_SILENCE_RUN_FRACTION`.

Do NOT use filename blacklists — they rot. Do NOT use total silence ratio alone:
the metric above is what actually separates the corpus.

## 2b. Decision (Hermes — D11): ffmpeg must be optional, never fatal

CI is red on `main` (run 39747015283): 3 of 4 `Test` jobs fail with

```
ERROR: test_cut_render_is_deterministic (test_engine.TestRenderer...)
  File "ai_dj/render.py", line 337, in ffmpeg_true_peak_dbtp
    raise RuntimeError("ffmpeg not found on PATH (required for true-peak check)")
RuntimeError: ffmpeg not found on PATH (required for true-peak check)
```

`render_plan()` must not hard-fail when ffmpeg is absent — the `Test` jobs do not
install ffmpeg (only the `E2E` job does, via `imageio-ffmpeg`). The existing
timing test already handles this correctly by skipping:

```
test_tempo_108_within_contract ... skipped 'ffmpeg not installed'
```

Fix both sides:
1. `ai_dj/render.py` — `ffmpeg_true_peak_dbtp()` returns
   `{"true_peak_dbtp": None, "integrated_lufs": None, "loudness_range_lu": None,
   "available": False}` instead of raising. The render still completes; the
   report records `"true_peak_measured_by": "unavailable: ffmpeg not on PATH"`
   and the loudness block is reported as not-measured. **Do not silently
   report 0.0** — that is fabrication (D6). The pre-scale by sample peak stays
   as the only protection when ffmpeg is missing, and the report must say so.
2. `tests/test_engine.py` — `test_cut_render_is_deterministic` skips when
   ffmpeg is not on PATH, mirroring `test_timing.py`.

Acceptance for this part: CI `Test` jobs on ubuntu 3.12/3.13 + windows 3.12 go
green with **zero** errors (skips are fine), and `render_plan` on a
ffmpeg-less machine returns a report with `true_peak_measured_by` containing
`unavailable` and does not raise.
