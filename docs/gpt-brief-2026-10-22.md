# BRIEF — AI DJ tự chủ trên Windows 11: phản biện kiến trúc trước khi triển khai

_Gửi cho GPT (thread "AI chơi DJ") ngày 22/10/2026. Verdict trả về: CONDITIONAL GO — engine Python P0._

## §A — Sự thật đã kiểm chứng (Hermes tự đo trên máy, 22/10/2026)

**Mục tiêu sản phẩm:** AI DJ chạy trên Windows 11, open source, tự chọn bài + tự chuyển bài đúng nhịp, phát liên tục một set (mục tiêu 60 phút), có bằng chứng đo được để nghiệm thu. Máy: Windows 11, RTX 3090 24GB, Ổ F còn 880GB, Node v24, Python 3.13.15 (đã có torch 2.8+cu129, fastapi, mcp).

**Đã cài và ĐÃ CHẠY THẬT (không phải suy đoán):**
- `ffmpeg 9.0.1 full build` có sẵn filter `rubberband` (time-stretch + pitch-shift chất lượng cao). Đã test: kéo tempo ×1.08 trên 1 file nhạc Việt thật → 152.5s thành 141.2s, tỉ lệ khoảng cách giữa các beat (IBI) đo được 1.0588 so với mục tiêu 1.08.
- Audio stack trên Python 3.13 venv: `librosa 1.0.0`, `numba 0.68`, `sounddevice 0.5.6`, `soundfile 0.14`. Đã mở output stream thật thành công (Realtek, FxSound, NVIDIA HDMI).
- Đã phân tích thật 5 file nhạc Việt: đọc được BPM, duration, RMS. Đường dẫn tiếng Việt có dấu không gây lỗi (một lần fail trước đó do truyền sai đường dẫn — đã sửa).
- **Cảnh báo đo được:** `librosa.feature.tempo` trả về 92–144 BPM cho các ca khúc Bolero (nghi lỗi octave — bậc 136 có thể thật là 68). Phải dùng trung vị IBI + chẩn đoán octave.

**Thư viện nhạc thật:** 55 file audio (WAV/MP3), cover Bolero/tình ca Việt, 150–330s, ở `F:\DỮ LIỆU\ok\` (kể cả `ok music\`). Đủ cho set 60 phút.

**Mixxx (đã đọc tài liệu + mã nguồn, chưa cài):**
- Chưa cài. Bản chính thức mới nhất 2.5. Mixxx **chính thức KHÔNG có OSC** (OSC chỉ ở fork `sandraschi/mixxxxx` → phải build C++/Qt).
- Bề mặt điều khiển chính thống = MIDI/HID controller mapping + **MIDI Scripting** (Mixxx 2.4+ chạy script trong QJSEngine ES7: `engine.setValue`, `engine.beginTimer`, `engine.getPlayer`). Nhưng script chỉ chạy khi có một thiết bị MIDI được chọn → trên Windows cần driver MIDI ảo (loopMIDI/rtpMIDI, **cần admin**).
- `pyrtmidi` **không cài được** (không có wheel cho Python 3.13/3.14 — pip báo "no versions available") → không tự tạo cổng MIDI ảo trong process được.
- Hệ quả: Executor dùng Mixxx = thêm 2 thành phần ngoài (app + driver cần admin) và **không đo được số học** → gate "mix đúng" phụ thuộc vào người nghe.

## §B — Phương án Hermes đề xuất + 4 câu hỏi chéo

**Kiến trúc đề xuất:** engine Python tự chứa (không Mixxx ở vòng này)
```
Thư viện nhạc (F:\DỮ LIỆU, WAV/MP3)
      ↓
[1] Analyzer   (librosa)  → BPM + key + downbeat + energy + intro/outro, cache sqlite
      ↓
[2] Brain       (Planner)  → set plan: thứ tự bài, loại transition, cue vào/ra, đường cong năng lượng
      ↓  plan.json (quyết định ÂM NHẠC — chạy 1 lần, không nằm trong vòng lặp thời gian thực)
[3] Renderer/Executor (deterministic) → beat-align + time-stretch (ffmpeg rubberband) + EQ + crossfade
      ↓  cùng một code path: realtime (sounddevice) và render-to-WAV (để đo)
[4] Ra master WAV (bản ghi để nghiệm thu) + phát realtime
```

**Câu 1 — Tầng engine:** bỏ Mixxx ở vòng này (không admin/driver, đo được số học, rubberband đủ chất lượng, kiến trúc nhỏ nhất), Mixxx giữ làm front-end tuỳ chọn ở P2. Có lỗ hổng nào khiến engine Python không đạt mức "DJ thật"?

**Câu 2 — Tầng Brain:** hybrid — planner theo luật làm nền (harmonic key + energy arc + ramp BPM), LLM chỉ gợi ý curator + diễn giải, không nằm trong đường timing. LLM có thực sự cần cho chất lượng âm nhạc không?

**Câu 3 — Phạm vi P0:** G0 → G1 → G2 → G3. Chấp nhận G0–G2 là P0 của vòng này (G3–G6 milestone sau)?

**Câu 4 — Môi trường:** không cài Mixxx / driver MIDI trong vòng này, chỉ dùng Python 3.13 venv trong project. Đồng ý?

**Điểm mù cần bắt:** (i) 55 file có đủ đa dạng cho set 60 phút không, hay cần lọc corpus? (ii) Gate số học có thay được việc nghe thật không? (iii) Rủi ro bỏ sót (drift tempo realtime, EQ/thanh trượt, độ trễ buffer)?
